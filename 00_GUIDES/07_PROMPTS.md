# 07. 제작 프롬프트

Claude Code 세션에 그대로 붙여넣어 쓰는 프롬프트 모음.

**조립 방법**: `A. 마스터` + `B. 카테고리 블록 1개` + `C. 항목 스펙 1줄` 을 이어 붙인다.
공통 규칙은 A에만 있으므로, 규칙이 바뀌면 A 한 곳만 고친다.

---

## A. 마스터 프롬프트 (항상 앞에 붙인다)

```text
너는 이 저장소의 PPT 템플릿 시스템에 들어갈 HTML 컴포넌트를 만든다.

## 먼저 읽을 것 (반드시 실제로 읽고 시작)
- 00_GUIDES/02_DESIGN_SYSTEM.md   토큰·수치
- 00_GUIDES/05_VISUAL_GUIDE.md    시각 판단 기준과 안티패턴
- 03_ASSETS/css/01_variables.css  사용 가능한 변수 전체
- 03_ASSETS/css/03_components.css 이미 있는 공통 클래스 (재정의 금지)

## 절대 규칙
1. 캔버스는 지정된 크기 고정. 단위는 px만. rem/vw/% 및 미디어쿼리 금지.
2. 색은 var(--color-*) 또는 var(--color-data-1~6)만. HEX 하드코딩 0개.
   계열 색은 data-1부터 순서대로. 6개를 넘기면 데이터를 묶어서 줄인다.
3. 간격은 8px 배수(var(--sp-*))만.
4. 도형·선·화살표는 인라인 <svg>. 텍스트는 HTML 요소.
   SVG <text>와 <img src="*.svg">는 쓰지 않는다.
5. SVG viewBox는 컴포넌트 크기와 1:1 ("0 0 <w> <h>").
6. 레이아웃은 flex + gap. position:absolute는 SVG 좌표에 텍스트를 겹칠 때만.
7. div 중첩 4단계 이내. class 이름은 의미 기반(step-card, funnel-stage).
   이 이름이 그대로 Figma 레이어 이름이 된다.
8. 애니메이션/transition/hover 상태 없음. 정적 캡처 대상이다.
9. backdrop-filter, mix-blend-mode, 다중 box-shadow, clip-path 곡선 금지.
10. 실제 한글 예시 문구를 넣는다. "Lorem ipsum", "제목1", "데이터A" 금지.
    발표에서 쓸 법한 실제 길이여야 오버플로우를 미리 발견할 수 있다.

## 디자인 판단
- 강조 대상은 1개, 강조 수단(크기/굵기/색/위치/여백)은 2개까지.
- accent 색 면적은 화면의 10% 이하.
- 그룹 내 간격 : 그룹 간 간격 = 1:2 이상.
- 노드 안 텍스트는 2줄 이내.
- 색만으로 구분하지 않는다. 라벨을 요소 옆에 직접 붙인다.
- 정렬축은 3개 이하. 모든 요소를 같은 축에 스냅한다.

## 파일 형식
1행은 반드시 이 마커. DOCTYPE 앞에 온다.
<!-- @card <제목> | <설명> | <가로>x<세로> -->

<head>에 공통 CSS 4개를 상대경로로 링크한다(순서 고정).
경로 깊이에 주의: 다이어그램은 ../../../, 그 외 컴포넌트는 ../../
  00_reset.css → 01_variables.css → 02_slide_base.css → 03_components.css

<body>는 <div class="component"> 하나로 감싼다(슬라이드는 class="slide").
이 컴포넌트에만 필요한 스타일은 <head>의 <style>에 둔다. 여기서도 색은 변수로.

## 완료 후 실행할 것
node tools/build-gallery.js
그리고 아래를 직접 확인해 보고한다.
- manifest에서 해당 항목 status가 done으로 바뀌었는지
- 하드코딩된 색이 0개인지 (검색해서 확인)
- .component 밖으로 넘치는 요소가 없는지

## 보고 형식
만든 파일 경로, 크기, 사용한 data 계열 수, 판단이 갈렸던 지점 1~2개.
지침을 어긴 곳이 있으면 숨기지 말고 이유와 함께 밝힌다.
```

## B. 카테고리별 블록 (해당하는 것 1개만 붙인다)

### B-1. 01_PROCESS_FLOW — 프로세스 · 흐름

```text
## 이 카테고리의 제약
- 진행 방향은 좌→우 또는 상→하 하나로 고정. 섞지 않는다.
- 단계는 4~6개. 7개를 넘으면 단계를 묶는다.
- 화살표는 <defs>의 marker 하나를 정의해 재사용한다.
  <marker id="arrow-<파일명약어>" ... orient="auto-start-reverse">
  id는 파일 안에서 유일해야 한다(다른 다이어그램과 합칠 때 충돌 방지).
- 단계 간격은 균등. flex + gap으로 분배하고 좌표를 하나씩 찍지 않는다.
- 마지막 단계(결과)만 accent 색. 나머지는 --color-surface 또는 data 색 순서.
- 각 단계에 번호를 붙인다. 화살표만으로는 순서가 안 읽힌다.
```

### B-2. 02_HIERARCHY_TREE — 계층 · 관계

```text
## 이 카테고리의 제약
- 계층은 3단계까지. 4단계는 1080p에서 글자가 18px 아래로 떨어진다.
- 커넥터는 직각(ㄱ자) path. 부모 아래 고정 y에서 가로로 이동한 뒤 자식으로 내린다.
    M px,py+30  L px,py+50  L cx,py+50  L cx,cy-30
  대각선으로 바로 잇지 않는다. 자식이 3개 이상이면 선이 겹쳐 보인다.
- 같은 계층 노드는 같은 크기·같은 y. 내용 길이가 달라도 맞춘다.
- 계층 구분은 색상이 아니라 같은 색의 명도 단계로 한다(순서에 의미가 있으므로).
- 마인드맵·관계도만 곡선 커넥터(C 명령) 허용.
```

### B-3. 03_MATRIX_SWOT — 매트릭스 · 4분면

```text
## 이 카테고리의 제약
- 4분면은 정확히 균등 분할. 축은 중앙을 지난다.
- 사분면마다 이름을 반드시 표기한다(색만으로 구분 금지).
- 축 라벨은 양 끝에 배치하고 방향 화살표를 넣는다(낮음→높음).
- 버블 크기로 값을 표현할 때는 지름이 아니라 "면적"에 비례시킨다.
  r = k * sqrt(value). 지름 비례는 값을 과장한다.
- 표 형태(비교/RACI)는 <table>을 쓴다. 헤더 행만 --color-surface-alt로 구분하고
  세로 구분선은 넣지 않는다.
- 자사/핵심 항목 1개만 accent로 강조.
```

### B-4. 04_VENN_CYCLE — 교집합 · 순환

```text
## 이 카테고리의 제약
- 벤다이어그램 원은 fill-opacity 0.35 전후. 겹친 부분이 색으로 읽혀야 한다.
  mix-blend-mode는 Figma에서 깨지므로 쓰지 않는다.
- 3원 벤은 정삼각 배치. 중심 간 거리 = 반지름 * 1.1 전후로 교집합을 확보한다.
- 교집합 라벨은 HTML 텍스트로 겹쳐 놓는다. 위치는 SVG 좌표에서 계산한다.
- 순환 화살표는 <path> 아크(A 명령). 각 아크 사이에 간격을 두어 단계를 분리한다.
  4단계면 각 아크 80도 + 간격 10도.
- 순환은 시계 방향 고정. 중앙에 주제를 넣는다.
- 허브앤스포크는 스포크를 균등 각도로 배치한다. 각도 = 360 / n.
```

### B-5. 05_PYRAMID_LAYER — 피라미드 · 레이어

```text
## 이 카테고리의 제약
- 층은 3~5개.
- 피라미드/깔때기 단면은 <polygon>으로 각 층을 따로 그린다.
  하나의 삼각형을 선으로 나누지 않는다(Figma에서 층별 편집이 불가능해진다).
- 층 사이에 2~4px 간격을 둔다. 맞붙이면 경계가 안 보인다.
- 설명 텍스트는 도형 안이 아니라 우측에 배치하고 층과 y를 맞춘다.
  도형 안에는 층 이름만(1줄).
- 색은 위→아래 명도 단계. 무지개색으로 칠하지 않는다(순서 정보가 사라진다).
- 수치가 있으면 각 층에 직접 표기한다. 축이나 범례를 만들지 않는다.
```

## D. 슬라이드 템플릿 프롬프트

슬라이드는 다이어그램과 규칙이 다르므로 마스터 프롬프트에 이 블록을 더한다.

```text
## 슬라이드 추가 제약
- 캔버스는 <div class="slide">. 1920×1080 고정.
- 세이프 영역을 지킨다: <div class="slide-inner"> 안에만 콘텐츠를 넣는다.
  (패딩 var(--slide-pad). 배경 이미지만 예외)
- 12컬럼 그리드에 스냅. 2단=6+6, 3단=4+4+4, 사이드바형=4+8.
- 콘텐츠 영역을 60~75%만 채운다. 80%를 넘으면 답답하다.
- 본문 한 줄은 45자 이내. 1728px를 꽉 채우면 60자가 넘어 읽기 어렵다.
- 자기완결형 단일 파일로 만든다. 외부 <link>를 쓰지 않고 CSS 전체를 <style>에 넣는다.
  기존 슬라이드 하나를 복사해 시작하면 공통 CSS를 그대로 물려받는다.
- <style> 안 순서: 공통 CSS → 테마 토큰(.v1/.v2/.v3) → 그 슬라이드의 레이아웃.
- .slide에 베리에이션 클래스를 붙인다: <div class="slide v2">
- 1행에 갤러리 마커를 넣는다:
  <!-- @card V2 콘셉트명 · 표지 | 한 줄 설명 | 1920x1080 -->
- 같은 스타일의 3 베리에이션은 화면 분할 구조가 서로 달라야 한다.
  색만 바꾼 것은 베리에이션이 아니다. 기획은 00_GUIDES/PLANS/ 를 따른다.
```

**작업 순서 권장**: 표지 1장을 먼저 끝내고 전역을 거기서 파생시킨다 →
`node tools/check-templates.js && node tools/build-gallery.js` →
갤러리에서 3 베리에이션을 나란히 놓고 **분할 구조가 실제로 다른지** 확인.
색만 다르면 기획으로 되돌아간다.

## E. 검수 프롬프트 (만든 뒤 별도로 실행)

```text
방금 만든 <파일경로>를 00_GUIDES/05_VISUAL_GUIDE.md §4 완성 판정 기준으로 검수해라.
호의적으로 보지 말고, 어긴 항목을 찾는 것이 목적이다.

각 항목을 실제로 확인하고 통과/실패로 답한다. 확인 방법도 같이 적는다.
- 하드코딩 색: 파일에서 # 로 시작하는 색값을 실제로 검색해 개수를 센다
- 간격: 8px 배수가 아닌 px 값이 있는지 센다
- viewBox: 컴포넌트 크기와 일치하는지 대조
- accent 면적: 대략 몇 %인지 추정하고 근거를 댄다
- 오버플로우: 요소 좌표+크기 합이 캔버스를 넘는지 계산

실패한 항목은 고친 뒤 node tools/build-gallery.js 를 다시 실행한다.
고칠 수 없는 항목(예: 지침끼리 충돌)은 고치지 말고 충돌 내용을 보고한다.
```
