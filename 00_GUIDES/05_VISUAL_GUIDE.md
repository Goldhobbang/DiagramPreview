# 05. 시각 지침 (디자인 판단 기준)

[02_DESIGN_SYSTEM.md](02_DESIGN_SYSTEM.md)가 **숫자**(폰트 크기, 간격 값, 토큰 이름)를 정한다면,
이 문서는 **판단**을 정한다 — 어디에 놓을지, 무엇을 강조할지, 무엇을 하지 말지.

숫자는 지켰는데 못생긴 슬라이드가 나오는 이유는 대부분 여기 있다.

---

## 1. 시각 원칙 6가지

### 1-1. 정렬 — 축은 3개 이하

한 화면에서 눈이 따라가는 세로선·가로선이 4개를 넘으면 산만해진다.

```
❌ 제목은 왼쪽 96, 부제는 왼쪽 120, 본문은 왼쪽 96, 카드는 왼쪽 140
✅ 전부 왼쪽 96. 들여쓰기가 필요하면 96 → 96+32 처럼 간격 스케일 값만 사용
```

- 모든 요소는 **12컬럼 그리드 선에 스냅**한다. 어중간한 위치 금지
- 가운데 정렬은 **표지·섹션 구분·인용**에만. 본문 슬라이드에서 가운데 정렬은 읽기 어렵다
- **광학 정렬**: 원·삼각형·화살표는 수학적 중앙이 아니라 시각 중앙에 맞춘다.
  삼각형을 원 안에 넣으면 무게중심이 왼쪽으로 쏠려 보이므로 1~2px 오른쪽으로 민다

### 1-2. 여백 — 남는 게 아니라 배치하는 것

**근접성 법칙**: 가까운 것끼리 한 덩어리로 읽힌다. 그룹 간 간격은 그룹 내 간격의 **2배 이상**.

```
✅ 카드 안 제목-설명 간격 16px  /  카드와 카드 사이 32px   (1:2)
❌ 카드 안 24px  /  카드 사이 32px   → 어디까지가 한 카드인지 안 보임
```

- 슬라이드가 비어 보인다고 요소를 채우지 않는다. **여백이 곧 강조**다
- 콘텐츠 영역(1728×888)을 80% 이상 채우면 답답하다. 60~75%가 적정
- 세이프 영역(패딩 96px)은 절대 침범하지 않는다. 배경 이미지만 예외

### 1-3. 위계 — 1차 정보는 슬라이드당 1개

발표자가 "이 장에서 하고 싶은 말 한 문장"을 못 대면 슬라이드를 쪼개야 한다.

| 층 | 역할 | 크기 |
|---|---|---|
| 1차 | 이 슬라이드의 결론 | H1 64px 또는 강조된 수치 |
| 2차 | 근거 · 구성 요소 | H3 32px |
| 3차 | 부연 · 출처 | Body-M 24px / Caption 18px |

**층은 3개까지.** 4단계 위계는 청중이 구분 못 한다.

### 1-4. 강조 — 수단은 2개까지, 대상은 1개

강조 수단은 **크기 / 굵기 / 색 / 위치 / 여백** 5가지.
한 요소에 **최대 2개**만 겹쳐 쓴다.

```
✅ 큰 숫자 + accent 색                (크기 + 색)
❌ 큰 숫자 + accent 색 + 굵게 + 밑줄 + 박스   (다 쓰면 아무것도 안 튀어나옴)
```

- **accent 색은 화면 면적의 10% 이하.** 절반이 파란색이면 파란색은 더 이상 강조가 아니다
- 한 화면에 강조가 2개면 둘 다 죽는다. 정말 2개가 필요하면 슬라이드를 나눈다

### 1-5. 반복 — 같은 역할은 같은 모양

- 카드 3개를 놓으면 3개 다 **같은 크기, 같은 패딩, 같은 라운드**
- 내용 길이가 달라도 높이를 맞춘다 (`align-items: stretch`)
- 단계 번호 원은 전부 같은 지름. "1"과 "10"의 폭이 달라도 원은 고정

예외는 딱 하나 — **의도적으로 하나만 다르게 만들어 강조할 때.** 그때는 확실히 다르게 한다.

### 1-6. 대비 — 목표는 7:1

WCAG AA 기준은 4.5:1이지만 **프로젝터·회의실 조명은 실측 대비를 크게 떨어뜨린다.**
화면에서 충분해 보이는 회색 글씨가 발표장에서는 안 보인다.

| 용도 | 목표 대비 |
|---|---|
| 본문 텍스트 | 7:1 이상 |
| 부가 설명(`--color-text-muted`) | 4.5:1 이상 |
| 도형 위 텍스트 | 7:1 이상 (반투명 배경 위는 특히 주의) |

**색만으로 구분하지 않는다.** 색 + 라벨, 색 + 패턴, 색 + 위치를 같이 쓴다.
남성 20명 중 1명은 적록 색약이다.

## 2. 다이어그램 제작 패턴

### 2-1. SVG와 HTML을 어디서 나누나

| 요소 | 어디로 | 이유 |
|---|---|---|
| 도형(원·사각·다각형) | **인라인 SVG** | Figma에서 편집 가능한 벡터 레이어 |
| 선 · 화살표 · 커넥터 | **인라인 SVG** | 좌표 계산이 정확하고 벡터로 들어옴 |
| 텍스트 | **HTML** | Figma에서 편집 가능한 텍스트 레이어. SVG `<text>`는 편집이 불편 |
| 카드 · 배지 · 버튼 | **HTML** | flex → Figma Auto Layout으로 변환됨 |
| 아이콘 | **인라인 SVG** | `<img src="*.svg">`는 단일 이미지로 뭉친다 |

**원칙: 배경 레이어는 SVG 1장, 그 위에 HTML을 얹는다.**

### 2-2. 좌표계를 1:1로 맞춘다

SVG `viewBox`를 컴포넌트 크기와 **똑같이** 잡는다. 그러면 SVG 좌표 = CSS px가 되어
HTML 오버레이 위치를 암산으로 맞출 수 있다.

```html
<div class="component" style="width:1400px;height:700px;position:relative">
  <!-- 배경: 도형과 선 -->
  <svg width="1400" height="700" viewBox="0 0 1400 700"
       style="position:absolute;inset:0">
    <circle cx="200" cy="350" r="60" fill="var(--color-data-1)"/>
  </svg>

  <!-- 오버레이: 텍스트. SVG의 (200,350)과 같은 좌표계 -->
  <div style="position:absolute;left:140px;top:320px;width:120px;text-align:center">
    <span class="t-h3">1단계</span>
  </div>
</div>
```

viewBox를 `0 0 100 100` 같은 정규화 좌표로 잡으면 오버레이 위치를 매번 환산해야 하고,
선 굵기가 스케일에 따라 달라진다. **하지 않는다.**

> 다이어그램 안에서 `position:absolute`는 이 경우에 한해 허용한다 — SVG 좌표에 맞춰야 하므로.
> 그 외 레이아웃(카드 나열, 행/열 배치)은 `flex` + `gap`을 쓴다.

### 2-3. 화살표는 marker 하나를 재사용

```html
<svg width="1400" height="700" viewBox="0 0 1400 700">
  <defs>
    <marker id="arrow" viewBox="0 0 10 10" refX="9" refY="5"
            markerWidth="6" markerHeight="6" orient="auto-start-reverse">
      <path d="M0,0 L10,5 L0,10 z" fill="var(--color-border)"/>
    </marker>
  </defs>
  <line x1="260" y1="350" x2="380" y2="350"
        stroke="var(--color-border)" stroke-width="2" marker-end="url(#arrow)"/>
</svg>
```

- `orient="auto-start-reverse"` — 선 방향을 따라 자동 회전
- `id`는 파일 안에서 유일해야 한다. 여러 다이어그램을 한 슬라이드에 합칠 때를 대비해
  `arrow-funnel` 처럼 접두사를 붙이면 안전하다

### 2-4. 커넥터 그리는 법

| 종류 | path | 쓰는 곳 |
|---|---|---|
| 직선 | `M x1 y1 L x2 y2` | 단계 흐름 |
| 직각 (ㄱ자) | `M x1 y1 L mx y1 L mx y2 L x2 y2` | 조직도, 트리 |
| 곡선 | `M x1 y1 C cx1 cy1 cx2 cy2 x2 y2` | 마인드맵, 관계도 |
| 아크 | `M x1 y1 A r r 0 0 1 x2 y2` | 순환 다이어그램 |

**조직도 직각 커넥터**는 부모 아래 중간점 `mx`를 부모와 자식 x의 중간이 아니라
**부모 바로 아래 고정 y**로 잡아야 선이 겹치지 않는다.

```
부모 (px, py)  →  M px py+30  L px py+50  L cx py+50  L cx cy-30
                  ↑아래로     ↑가로로 이동   ↑자식 위로
```

### 2-5. 반복 요소는 flex + nth-child

노드 5개를 좌표로 하나씩 찍지 않는다. 균등 분배는 flex에 맡기고 색만 바꾼다.

```html
<div class="row" style="gap:32px">
  <div class="card d1">…</div>
  <div class="card d2">…</div>
  <div class="card d3">…</div>
</div>
```
```css
.card { flex: 1; border-top: 4px solid var(--c); }
```

`d1`~`d6` 클래스는 [03_components.css](../03_ASSETS/css/03_components.css)에 이미 있다.
`--c` 변수를 세팅해주므로 `var(--c)`로 받아 쓴다.

### 2-6. 색 배정 규칙

- 계열 색은 `--color-data-1` 부터 **순서대로**. 건너뛰지 않는다
- **6개를 넘기면 데이터를 묶는다.** 7색 이상은 사람이 범례와 대조하지 못한다
- 순서에 의미가 있으면(단계, 성숙도) 색상 대신 **같은 색의 명도 단계**를 쓴다
- 좋음/나쁨을 표현할 때만 `--color-positive` / `--color-negative`

**색은 도형에, 텍스트는 잉크로.** 본문은 항상 무채색 계열(`--color-text` /
`--color-text-muted`)로 둔다. 유채색 본문은 프로젝터에서 대비가 무너진다.
색이 많아 보이는 인상이 필요하면 큰 면 하나가 아니라 **작은 조각 여러 개**로 만들고,
장식 면적 합계를 화면의 35% 이하로 묶는다. 색이 늘어도 **강조 대상은 1개**다.

## 3. 안티패턴 — 하지 말 것

### 3-1. 그라디언트 남발
- 그라디언트는 **배경 1곳**에만. 텍스트·아이콘·작은 도형에는 쓰지 않는다
- 색상환에서 먼 두 색(파랑→노랑)을 섞으면 중간에 탁한 회색이 생긴다. 인접 색끼리 쓴다
- 예외: 그라데이션이 스타일 정체성인 경우(`15_SOFT_GRADIENTS` 등)에도 정지점은 3개 이내,
  인접색 90° 이내를 지키고 노이즈 4~8%를 얹어 밴딩을 막는다

### 3-2. 의미 없는 아이콘
- "회의"에 말풍선, "성장"에 화살표처럼 **단어를 그림으로 번역만 한 아이콘**은 정보를 0 더한다
- 아이콘은 **구분이 필요할 때**만. 항목 5개를 서로 구별해야 한다면 유용하다
- 한 화면에 아이콘 스타일 2종 혼용 금지 (선형 + 면형 섞지 않기)

### 3-3. 글자 과다
- 다이어그램 노드 안 텍스트는 **2줄 이내**. 넘치면 그건 다이어그램이 아니라 표다
- 슬라이드 본문은 **한 줄 45자 이내**. 1728px 폭에 28px 글자를 꽉 채우면 60자가 넘어 읽기 어렵다
  → 2단으로 나누거나 폭을 제한한다
- 불릿은 **6개 이내**. 넘으면 그룹으로 묶는다

### 3-4. Figma에서 깨지는 CSS
전체 목록은 [01_FIGMA_IMPORT_GUIDE.md §6](01_FIGMA_IMPORT_GUIDE.md) 참조. 자주 걸리는 것:

| 하지 말 것 | 대신 |
|---|---|
| `backdrop-filter` | 반투명 배경색 |
| `mix-blend-mode` | `rgba()` |
| 다중 `box-shadow` | 그림자 1개 |
| `<img src="*.svg">` | 인라인 `<svg>` |
| SVG `<text>` | HTML 텍스트 오버레이 |
| CSS 애니메이션 | 최종 상태를 기본값으로 |

### 3-5. 가짜 3D · 원근
- 원통형 막대, 입체 원그래프, 기울어진 평면 — **면적을 왜곡해 데이터를 거짓말하게 만든다**
- 그림자는 깊이 표현용이 아니라 **레이어 구분용**으로만 (`--shadow-sm` 수준)

### 3-6. 데이터 없는 장식
- 눈금이 없는 축, 값이 없는 막대, 축 라벨 없는 산점도
- **차트에 실제 숫자를 넣는다.** "Lorem"이나 "데이터1"은 임포트 후 길이 감이 안 잡혀 금지
- 격자선은 최소로. 값을 직접 표기할 수 있으면 축 자체를 지운다

### 3-7. 색만으로 구분
- 범례를 색 칩으로만 만들지 않는다. **라벨을 요소 옆에 직접 붙인다**
- 4분면 다이어그램은 색 + 사분면 이름을 같이 표기
- 흑백 인쇄해도 구분되는지 한 번 확인 (`filter: grayscale(1)`을 임시로 걸어본다)

### 3-8. 축이 어긋난 배치
- SVG 도형과 HTML 텍스트의 중심이 1~2px 어긋나면 **확대했을 때 티가 난다**
- 원 안 텍스트: `left: cx - w/2`, `top: cy - h/2` 를 계산해서 넣는다
- 계산하기 싫으면 flex로 감싸 `justify-content:center; align-items:center`

## 4. 완성 판정 (다이어그램 1개 기준)

- [ ] 1행에 `@card` 마커가 있고 크기가 실제와 일치
- [ ] 색이 전부 `var(--color-*)` 또는 `var(--color-data-N)` — 하드코딩 0
- [ ] 도형은 인라인 SVG, 텍스트는 HTML
- [ ] `viewBox`가 컴포넌트 크기와 1:1
- [ ] 강조 대상 1개, 강조 수단 2개 이하
- [ ] accent 면적 10% 이하
- [ ] 그룹 내 간격 : 그룹 간 간격 = 1:2 이상
- [ ] 노드 텍스트 2줄 이내, 실제 한글 예시 문구
- [ ] `filter:grayscale(1)` 걸어도 항목 구분이 됨
- [ ] `.component` 밖으로 넘치는 요소 없음
